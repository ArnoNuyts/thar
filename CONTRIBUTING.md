# Contributing

Thanks for helping improve thar.

## Setup

Node is pinned in `.nvmrc`.

```sh
nvm use
npm ci
npm test
npm run check
npm run build
```

## Branches

- Open feature and fix PRs against `release/next`.
- Merges to `release/next` publish a beta release.
- `release/next` is promoted to `main` with a PR; merges to `main` publish a
  stable release.
- `main` and `release/next` are protected: use a PR, never a direct push.

Bump `version` in `package.json` in any PR that should produce a stable release.
Beta versions are generated by CI.

## Pull requests

- Keep the change focused and include tests where behavior changes.
- Run `npm test` and `npm run check` before opening the PR.
- Describe the user-visible change and how you verified it.

Release details live in [docs/RELEASING.md](docs/RELEASING.md).

## Demo GIF

The README demo is generated with [VHS](https://github.com/charmbracelet/vhs):

```sh
vhs docs/demo.tape
```

The tape copies `docs/demo.todo.txt` to a temporary file, so re-recording never
changes the fixture.
